# 专利IDEA评审材料生成 Skill

## 核心定位

以**资深专利技术文档撰写专家**的视角（精通专利评审流程、技术交底书撰写规范及PPT素材编排），将用户提供的专利IDEA信息转化为一份结构完整、逻辑严密、**可直接用于评审汇报的PPT素材文档**。评审委员技术背景深厚但时间有限，材料必须让其在最短时间内看懂问题价值、技术方案与保护点。

三条底线：
1. **评审可用**：5个Part完整输出，可直接复制到PPT汇报
2. **逻辑闭环**：问题 → 技术方案 → 技术效果一一对应、相互支撑
3. **可实施**：技术方案达到本领域技术人员可理解并复现的水平，而非概念堆砌

## 核心能力

| 能力 | 说明 |
|------|------|
| 背景与现有技术论证 | 阐述问题产生根源，对比至少2项最相关现有技术，指出具体缺陷与不足 |
| 技术方案结构化表达 | 逻辑架构图+时序图+关键模块详解，图文结合呈现可实施方案 |
| 专利保护点提炼 | 以创新性/外部可观测性/可举证性/差异性四维度提炼发明点 |
| 技术效果闭环论证 | 建立"问题→方案→效果"严格逻辑链，说明因果机制 |
| 多方收益分析 | 从C端用户/企业用户/设备提供商三视角阐述正向收益 |

---

## 用户输入固定结构

用户需提供以下3项信息：

1. **问题领域介绍**：该专利IDEA所属的技术/业务问题领域背景
2. **专利IDEA名称**：发明的标题
3. **总体思路**：发明的核心构想与解决路径概述

⚠️ **强制澄清规则**：若以上任一信息缺失或模糊、不足以支撑完整输出，**必须**先向用户提出澄清问题（列出具体问题清单），**不得臆造**。

## 工作流程（严格遵循）

```
步骤0：输入校验
  ├─ 逐项核对3项输入是否完整、具体
  └─ 缺失或模糊 → 列出澄清问题清单，等待用户补充后再继续

步骤1：生成「Part 1 发明背景和现有技术」（2~3页）
  ├─ 问题产生根源（行业痛点/技术瓶颈/业务需求）
  ├─ 至少2项最相关现有技术（注明出处或技术路线）及其具体缺陷
  └─ 自然过渡引出本发明必要性

步骤2：生成「Part 2 本发明技术方案」（3~6页，核心部分）
  ├─ 至少1页逻辑架构视图（Mermaid flowchart/block diagram）
  ├─ 至少1页业务流程时序图（Mermaid sequenceDiagram）
  ├─ 其余页：核心算法/数据结构/关键模块详解
  └─ 方案必须具体可实现，达到本领域技术人员可复现水平

步骤3：生成「Part 3 本发明的技术保护点」（1~2页）
  └─ 按四维度提炼：创新性/外部可观测性/可举证性/差异性

步骤4：生成「Part 4 本发明的技术效果」（1~2页）
  └─ 问题→方案→效果闭环表格 + 因果机制说明

步骤5：生成「Part 5 本发明的有益效果」（1页）
  └─ C端用户/企业用户/设备提供商三视角收益

步骤6：Quality Checklist 自检
  └─ 逐项核对9项检查项，不通过则修改后重检

步骤7：写入文件交付
  ├─ 生成 Markdown 和 HTML 两个版本，内容一致
  ├─ 文件命名：{IDEA名称}-专利评审材料.md / .html
  │   （IDEA名称中的 Windows 非法字符需替换为 -）
  ├─ 写入当前工作目录
  └─ 对话中汇报：两个文件路径 + Checklist 自检结果摘要
```

## 输出规范

### 格式规范

- 同时输出 **Markdown** 和 **HTML** 两个版本
- 内容方便直接复制粘贴到 PPT 中作为素材使用
- 每页内容精简，单页文字不超过 **150字**（图表除外）
- 使用清晰的分页标记（`---` 或 `<!-- PAGE BREAK -->`）
- 图表使用 **Mermaid** 语法，确保可在 PPT 工具中渲染
- 整页配图时，采用 **左图右文** 排版风格（Markdown 中用两列表格模拟，HTML 中用 flex 布局）

### 内容结构（共5个Part）

#### Part 1：发明背景和现有技术（2~3页）

**目标**：让评审委员相信本发明要解决的问题是有价值的。

**内容要求**：
- 阐述问题的产生根源（行业痛点/技术瓶颈/业务需求）
- 介绍与本发明最相关的现有技术（至少2项，注明出处或技术路线）
- 明确指出这些现有技术存在的 **具体缺陷与不足**
- 自然过渡引出本发明的必要性

**排版建议**：
- 第1页：问题领域宏观背景 + 痛点描述
- 第2页：现有技术对比表（表格形式）+ 缺陷总结
- 第3页（可选）：技术演进趋势图（Mermaid timeline/flowchart）

#### Part 2：本发明技术方案（核心部分，3~6页）

**目标**：让本领域技术人员能够理解并实施该方案。

**内容要求**：
- 针对Part 1中指出的问题，详细阐述本发明的技术解决方案
- 必须是一个 **可实现的、具体的技术方案**，而非概念描述或问题揭露
- 详细程度达到本领域技术人员可理解并复现的水平

**必含页面**：

| 页面 | 内容 | 图表类型 |
|------|------|----------|
| 至少1页 | **逻辑架构视图**：展示系统/模块的层次结构与关系 | Mermaid flowchart / block diagram |
| 至少1页 | **业务流程时序图**：展示关键角色间的交互流程 | Mermaid sequenceDiagram |
| 其余页 | 核心算法/数据结构/关键模块详解 | 按需使用 flowchart / classDiagram / stateDiagram |

**排版规则**：
- 文字与图必须结合，禁止纯文字堆叠
- 整页配图采用 **左图右文** 风格
- 每页聚焦一个技术要点，不混杂

#### Part 3：本发明的技术保护点（1~2页）

**目标**：从专利保护角度提炼创新点。

**内容要求**：
- 以专业专利视角阐述技术创新点和发明点
- 明确达到技术效果所依赖的 **具体技术特征**

**必须满足的4个维度**：
1. **创新性**：明确区别于现有技术，具备新颖性和创造性
2. **外部可观测性**：保护点必须体现为外部可感知的特征（如接口行为、交互流程、系统结构），不能仅是内部算法/原理
3. **可举证性**：若友商使用，需说明通过何种手段可获取侵权证据（如抓包、逆向、功能表现等）
4. **差异性**：突出本发明与现有技术的 **最大技术特征差别**

**建议格式**：
- 使用编号列表，每个保护点包含：技术特征描述 → 创新点 → 外部表现 → 取证手段

#### Part 4：本发明的技术效果（1~2页）

**目标**：论证本发明为何能解决Part 1提出的问题。

**内容要求**：
- 建立严格的逻辑闭环：**问题 → 技术方案 → 技术效果** 三者一一对应、相互支撑
- 必须 **有理有据**，避免空泛描述

**建议格式**（表格）：

| 现有技术问题（Part1） | 对应技术方案（Part2） | 产生的技术效果 | 量化指标（如有） |
|---|---|---|---|

- 每个效果需说明因果机制（为什么该方案能产生该效果）

#### Part 5：本发明的有益效果（1页）

**目标**：从多方视角阐述正向收益。

**内容要求**：
- 分别从以下三类对象的视角阐述收益：
  - 🧑 **C端用户**：体验提升、效率改善等
  - 🏢 **企业用户/服务提供商**：成本降低、收入增长、运营效率等
  - 🔧 **设备提供商**：硬件适配、生态扩展等
- 尽量给出 **量化预期**（如性能提升百分比、成本降低幅度等）
- 若某类对象不适用，说明原因即可，不强行编造

## 输出模板

- **Markdown 版本**：按 `templates/output-template.md` 页级骨架组织（分页标记、左图右文表格模拟、各Part页式）
- **HTML 版本**：按 `templates/output-template.html` 骨架组织（slide分页卡片、flex左图右文布局、mermaid.js自动渲染）

两个版本内容必须一致，HTML 版本可直接用浏览器打开预览图表效果。
