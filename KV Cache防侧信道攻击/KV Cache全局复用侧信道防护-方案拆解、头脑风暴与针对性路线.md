# KV Cache 全局复用侧信道防护：方案拆解、头脑风暴与针对性路线

**对象文档**：`KV Cache全局复用侧信道攻击方案解决方案报告（Qwen）.md`  
**分析目标**：跨站点、跨租户/用户、跨会话 KV Cache 全局复用所引入的时序侧信道  
**分析日期**：2026-11-10

---

## 0. 结论先行

Qwen 报告中最有价值的一点，是提出了：

> **把全局共享缓存的匹配粒度从 Token 级改成块级，使逐 Token 探测失去连续反馈。**

这是直接针对攻击链的机制，应当保留。

但该报告存在三个决定性问题：

1. **“独立来源数/热度晋升”不是公共性证明**——私有内容可能被多个租户、多个会话共享，攻击者也可以制造多租户、多会话来操纵晋升；热门机密文档同样会被晋升为“全局共享”。
2. **块级匹配只是切断逐 Token 梯度，不能单独解决缓存成员关系泄露**；如果私有块仍进入攻击者可查询的池，攻击者知道或猜全整块后仍可探测其存在性。
3. **区域蜜罐/背景 Batch 拖慢是攻击发生后的补救**，无法防低慢速分布式探测，也会误伤合法的批量化、模板改写和 A/B 测试流量，不能作为主防线。

因此，真正有针对性的方案不是继续堆“混淆”“随机延迟”“蜜罐”，而是同时打掉时序侧信道成立的两个必要条件：

> **① 攻击者能够进入受害者 KV 的查找空间；② 攻击者能够获得细粒度的命中反馈。**

推荐采用以下组合，而不是单点机制：

| 防线 | 机制 | 作用 |
|---|---|---|
| 一：可见性分层 | 公共池 / 授权共享池 / 用户-会话私有池 | 攻击者不能查询受害者私有 KV |
| 二：原子块匹配 | 共享池只接受完整原子块匹配 | 即使误入共享池，也无法逐 Token 恢复 |
| 三：内容来源准入 | 公共性由可审计来源证明，而非热度 | 从源头阻止私有内容进入全局池 |
| 四：发布时预热 | 共享内容由内容发布事件驱动填充 | 不把“某用户首次请求”作为缓存存在信号 |
| 五：观测去相关 | 不暴露命中状态、节点、计费差异 | 防止侧信道从其他接口重新出现 |

这五条组合起来，能够在**不增加人工延迟、不牺牲公共内容全局复用、不要求用户打标签**的前提下，把跨租户/跨用户私有内容探测变为不可行；仅放弃“两个无授权关系的租户碰巧拥有同一私有前缀”的复用。

## 1. 先看清攻击链：哪一步可以被真正切断

### 1.1 攻击成立的必要条件

逐 Token 时序侧信道并不是单一漏洞，而是以下链条：

```text
攻击者可控地构造候选前缀
        ↓
候选前缀与受害者的 KV 落在同一个匹配空间
        ↓
系统采用细粒度（Token/连续前缀）精确匹配
        ↓
命中与未命中产生显著时间差
        ↓
攻击者观测时间差并获得“下一个 Token 是否正确”的反馈
        ↓
逐 Token 迭代恢复私有内容
```

攻击成立必须同时具备：

1. **可控性**：攻击者可以微调输入，制造与受害者前缀的碰撞；
2. **共享性**：攻击者与受害者的 KV 进入同一命名空间/匹配池；
3. **细粒度**：系统对候选前缀给出足够细的匹配反馈；
4. **可观测性**：命中/未命中的差异能够被攻击者测量；
5. **可推断性**：攻击者能从反馈中迭代出内容。

### 1.2 防御点选择

| 防御点 | 做法 | 优点 | 局限 |
|---|---|---|---|
| 切断共享性 | 私有 KV 只进入所有者作用域 | 根本、无需增加延迟 | 放弃无授权私有内容的跨租户复用 |
| 粗化匹配粒度 | 共享池只做完整块匹配 | 不牺牲公共复用、不改响应时间 | 块成员关系仍可能被探测 |
| 切断可观测性 | 将命中时间对齐到最坏情况 | 理论彻底 | 严重损害体验、浪费算力 |
| 检测反制 | 识别探测后限速/隔离 | 可减轻滥用 | 反应式、有漏报误报、无法作为主防线 |

**关键判断**：

- 切断“可观测性”等于放弃命中加速，不现实；
- 纯检测反制无法应对分布式低慢速攻击；
- 只有**切断共享性 + 粗化匹配粒度**能够同时保住正常体验和大部分复用收益。

## 2. Qwen 三机制拆解

### 2.1 机制一：块级哈希匹配

**原方案**：前缀按 256/512 Token 切块，只有完整块进入全局目录，匹配不支持块内部分匹配。

**正确的部分**：

- 将攻击从“逐 Token 线性反馈”变成“必须一次猜中整块”，极大提高恢复成本；
- 对公共模板和完整 RAG 段落，合法用户仍可按块命中；
- 不需要增加响应延迟或额外重算。

**漏洞与未解决问题**：

1. **没有说明全局池是否允许私有内容进入**。如果私有内容仍可进入，攻击者只要知道或猜中整块，仍可探测成员关系；
2. **固定块大小仍存在“块尾单 Token 预测”问题**：如果攻击者已知一个块前 B−1 个 Token，只需猜最后 1 个 Token 即可获得块命中反馈；
3. **块边界可能被利用**：固定长度块在文档/前缀移位时不稳定，合法的部分复用会下降；攻击者也可能通过添加前缀改变边界（若实现按绝对位置切分）；
4. **全局块池与私有 Token 级缓存若并存，必须强制禁止共享池回退到 Token 级匹配**，否则攻击者仍可通过局部前缀触发反馈；
5. **块哈希值本身可能成为成员查询接口**：如果攻击者能枚举块哈希或访问目录，仍可获得“某块是否存在”的成员关系信息。

**结论**：机制一应保留，但必须升级为：

- 只对**公共池/授权共享池**使用；
- 采用**完整原子块、按内容定义边界**；
- 目录按作用域分区，块索引使用带作用域密钥的键；
- 共享池绝不回退到 Token 级前缀匹配；
- 私有池仍可做 Token 级前缀匹配，但只对同一用户/会话可见。

### 2.2 机制二：渐进式共享准入

**原方案**：按“独立来源数”从会话私有 → 租户私有 → 候选共享 → 全局共享推进。

**核心错误**：

> **独立来源数只能证明“重复出现”，不能证明“公共性”。**

具体问题：

1. **攻击者可制造独立来源**：云租户、会话、账号的获取成本可能很低，攻击者可以自己制造多个 Tenant/Session，把任意候选内容“刷”成共享状态；
2. **多租户共享不等于公共**：同一份泄露的机密文档、同一种敏感业务模板、同一个客户名单，可能被多个租户使用；热度越高，反而越容易被错误公开；
3. **晋升过程本身可能形成新侧信道**：攻击者可以观察候选前缀在多次请求后是否进入共享状态，从而推断受害者是否使用过该前缀；
4. **租户内部状态仍不安全**：从会话私有晋升到租户私有后，同租户的其他用户可能探测到本不属于自己的会话内容；
5. **无法区分“重复”与“授权”**：两个租户都拥有同一份文档，不代表它们有共享该文档缓存的授权关系。

**结论**：机制二应当改成**来源/授权准入**：

- 公共内容：由可审计的公共来源证明决定，而不是访问热度；
- 授权共享内容：按现有 ACL、项目成员关系、部署清单决定；
- 私有内容：默认留在用户或会话作用域，不因重复出现自动升格；
- 管理员策略可以显式定义共享组，但不采用“热度自动全局化”。

### 2.3 机制三：前缀区域异常检测与蜜罐调度

**原方案**：监控微小变异聚集度，把可疑区域请求塞入背景 Batch 物理拖慢。

**问题**：

1. **反应式**：攻击发生后才检测；
2. **低慢速分布式攻击**可以保持在阈值以下；
3. **误伤合法行为**：批量 Prompt 改写、A/B 测试、自动评测、模板生成、红队测试都表现为“高度相似但不完全相同”；
4. **背景 Batch 的拖慢不是确定性安全边界**：攻击者可换账号、换时间窗口、拆分请求；
5. **“不封禁、只拖慢”不等于无副作用**：被误判用户的延迟和吞吐会受到实际影响；
6. 若后续进一步加入“返回假数据”，还会引入正确性、误判责任和服务承诺问题。

**结论**：检测只能作为**滥用治理与容量保护**的辅助，不应作为隐私主防线。真正的主防线必须让攻击者在检测之前就无法访问受害者私有 KV。

## 3. 头脑风暴：十种可选路线

以下按“是否直接影响攻击链”评分。

| # | 思路 | 核心机制 | 保 UX | 保全局复用 | 安全效果 | 可落地性 | 结论 |
|---|---|---|---|---|---|---|---|
| 1 | 全部全局共享 + 全局延迟对齐 | 命中等待至未命中耗时 | 差 | 好 | 理论强 | 中 | 不可接受 |
| 2 | 全部全局共享 + 随机抖动 | 随机延迟掩盖时间差 | 中 | 好 | 弱，统计可滤除 | 高 | 不可作为安全方案 |
| 3 | 全部全局共享 + 命中时影子重算 | 命中仍走完整计算路径 | 理论不慢，但算力浪费 | 好 | 强 | 中 | 失去复用核心收益 |
| 4 | 只共享公共内容 | 私有内容完全隔离 | 好 | 公共复用保留 | 强 | 高 | **正确基础** |
| 5 | 热门内容自动全局化 | 独立来源数晋升 | 好 | 表面好 | 不安全 | 高 | 拒绝 |
| 6 | 全局原子块匹配 | 完整块才命中 | 好 | 公共/共享内容保留 | 阻断逐 Token 恢复 | 中 | **保留并升级** |
| 7 | ACL/项目授权共享池 | 按现有授权关系复用 | 好 | 授权内容可跨租户 | 强 | 高 | **推荐** |
| 8 | 发布时预热共享内容 | 内容发布而非请求触发缓存 | 更好 | 好 | 降低活动痕迹 | 中 | **推荐** |
| 9 | 诱饵缓存/全候选取样 | 预计算候选分支或假命中 | 可能好 | 差 | 理论上可混淆 | 低 | 成本不可接受 |
| 10 | 仅异常检测/蜜罐 | 行为识别后拖慢 | 有误伤 | 好 | 弱且反应式 | 高 | 只能辅助 |
| 11 | 目录/响应去相关 | 不暴露命中、节点、计费差异 | 好 | 好 | 关闭旁路 | 高 | **必做** |
| 12 | 存储级跨租户去重 | 物理块共享但逻辑不可见 | 好 | 存储收益 | 取决于索引隔离 | 中 | 可选增强 |

### 3.1 对“诱饵缓存”的进一步 brainstorm

有人会想到：给攻击者返回“假命中”或为所有可能候选预计算 KV，让攻击者无法区分。

这在理论上类似“全空间覆盖”，但实际不可行：

- 词汇表大小 V，块长度 B，需要预计算 V^B 个候选；
- 即使只覆盖一层候选，下一层仍会继续分叉；
- 假命中会让正常推理结果失真；如果假命中后仍需重算，时间又回到 Miss，攻击者仍能区分；
- 存储和算力成本随上下文长度和候选分支爆炸。

因此，**诱饵只能作为低价值补充，不能作为主方案**。

### 3.2 对“随机化/统计噪声”的进一步 brainstorm

随机延迟看似可以增加攻击难度，但：

- 攻击者可以对同一候选重复采样取中位数；
- 真正正确的候选命中概率高于错误候选，长期统计仍可分离；
- 要真正隐藏，随机延迟幅度必须接近命中/未命中差（数秒），直接破坏用户体验；
- 分布式攻击可以大量采样，噪声成本被攻击者预算摊销。

结论：**随机化不适合作为主防线**。

### 3.3 对“租户私有缓存”的进一步 brainstorm

如果所有私有内容只按租户隔离：

- 同租户不同用户之间仍可能探测；
- 一个被攻破的低权限员工账号可以试探同租户其他部门、其他用户；
- 因此需要进一步细化到**用户/会话/部门授权组**，而不是停在租户。

### 3.4 对“内容来源自动识别”的进一步 brainstorm

不要求用户打标签，并不等于系统不能利用来源：

- RAG 编排层天然知道文档 ID；
- Agent 框架天然知道 System Prompt 与工具模板；
- 企业部署天然有共享组和 ACL；
- 公共内容可以由平台/内容方登记；
- 未知来源的纯文本 Prompt，可以安全地默认到用户/会话私有。

这比“根据访问热度推断公共性”更可靠，也不需要识别内容是否敏感。

## 4. 推荐路线：三级可见性缓存 + 原子块 + 来源准入

### 4.1 三级缓存

```text
G 池：公共原子块池（Global Atomic Pool）
     - 只收公共来源内容
     - 跨站点、跨租户、跨会话
     - 完整原子块匹配

A 池：授权共享池（Audience Pool）
     - 只收有 ACL/项目/部署授权的共享内容
     - 在授权主体集合内跨用户、跨租户、跨站点
     - 完整原子块匹配

P 池：私有池（Principal/Session Pool）
     - 用户原始输入、对话历史、个人上下文
     - Token 级前缀缓存可保留，用于提升同用户体验
     - 仅同一用户/会话可查询
```

物理上三池可以共用同一套缓存节点、目录、网络和存储；逻辑上缓存查询只能进入请求者有权限的池。

### 4.2 一张请求路径

```text
请求
  → 认证（租户/用户/会话/应用）
  → 来源解析（公共资产 / 授权文档 / 用户私有）
  → 计算本请求可见的池与作用域
  → 按作用域查询：
       - G 池：精确公共原子块
       - A 池：授权主体范围内的原子块
       - P 池：本用户/本会话的 Token 级前缀
  → 命中：复用；未命中：正常 Prefill
  → 新块按来源血缘决定写入哪个池
  → 返回真实结果，不增加人工延迟
```

### 4.3 三级池的准入规则

| 内容类型 | 进入哪个池 | 准入依据 |
|---|---|---|
| 平台公共 System Prompt | G | 平台签名的公共资产登记 |
| 公共工具 Schema | G | 发布清单/公共注册表 |
| 公共开放文档 | G | 明确公共 ACL 或许可证 |
| 企业共享提示词 | A | 企业部署清单/管理员共享策略 |
| 项目共享文档 | A | 项目成员 ACL |
| 跨租户合作文档 | A | 跨租户授权关系 |
| 用户个人知识库 | P（用户级） | 用户归属 |
| 对话历史 | P（用户或会话） | 会话血缘 |
| 来源不明 Prompt | P | 默认私有 |
| 两个租户碰巧出现的相同私有文本 | 不共享 | 无授权关系，不做热度晋升 |

**不再采用“独立来源数自动晋升为全局共享”**。

## 5. 原子块匹配的完整设计

### 5.1 只对 G/A 池启用

- P 池：保留 Token 级前缀缓存，提高同一用户多轮、跨会话体验；
- G/A 池：只允许**完整原子块**命中。

攻击者在自己的 P 池里探测，只能命中自己写过的内容，不会获得受害者状态。

### 5.2 原子块定义

建议使用**内容定义分块（CDC）**而不是固定切分：

```text
对规范化 Token 序列做滚动哈希
在满足最小块长 B_min 的位置选择边界
块大小允许有界变化
块键 = H(scope || model_manifest || block_tokens || parent_commitment)
```

理由：

- 固定长度分块在文档插入、删除、移位时边界不稳定；
- 内容定义分块在相同文档前缀上边界稳定，更适合 RAG/文档复用；
- 攻击者必须一次性提供完整块，才能触发 G/A 池命中；
- 对最后一个不完整块，留在 P 池，不进入 G/A 池。

参数 `B_min` 由工作负载决定，不能拍脑袋固定为 512；需要权衡：

- 块越大：越能抗 Token 级探测，但合法部分复用越少；
- 块越小：合法复用越好，但块尾预测和成员关系颗粒更细。

### 5.3 共享池不得回退到 Token 匹配

这是该机制能否成立的关键实现约束：

```text
G/A 池查询：
    完整块命中 → 复用
    不完整块/块内前缀 → 不命中
    禁止为了提升命中率回退到 Token 级前缀匹配
```

否则攻击者只要命中公共块后继续逐 Token 试探，就会重新获得反馈。

### 5.4 块级残余风险

原子块并非“绝对安全”：

- 如果攻击者已经知道一个块前 B−1 个 Token，只猜最后一个 Token，仍可能获得一次块命中反馈；
- 如果攻击者通过其他渠道获得完整块，可以测试“该块是否存在于某池”；
- 因此仍需**可见性隔离**和**目录保护**，不能单靠块匹配。

正确表述应是：

> 原子块把逐 Token 线性恢复变为“需要先知道几乎整个块”的稀疏成员探测，显著降低泄露速率和可恢复内容；它不能消灭所有成员关系泄露。

---

## 6. 来源准入：公共性由“证明”决定，而不是热度

### 6.1 公共来源证明

G 池只接受可审计的公共证据，例如：

1. 平台签名的公共 System Prompt/工具包；
2. 内容登记为 public 的 RAG 对象；
3. 带有明确开放许可证的公共语料；
4. 企业明确发布到“全员/公开租户组”的共享资产；
5. 运营商登记的热门公共模板。

系统不为普通用户请求执行“语义敏感性识别”，也不因为某文本被很多租户访问就自动升格。

### 6.2 A 池授权来源

A 池依据现有 ACL/项目/部署关系：

- 文档 ID → 读取 ACL；
- 项目 → 读取成员集合；
- 租户部署 → 读取管理员共享策略；
- 跨租户共享 → 读取合作项目授权。

授权主体集合变化时，A 池条目的策略版本立即失效；旧授权用户不再能看到新版本条目。

### 6.3 P 池默认私有

- 有最终用户身份：用户级，可跨会话；
- 只有应用/租户 API Key：会话级；
- 无稳定身份：请求级；
- 未识别来源：用户/会话级，不会自动进入 G/A。

这实现了“不依赖用户配合”，但依赖的是系统已有的身份、ACL 和来源元数据，而不是让用户逐请求打标签。

### 6.4 对 Qwen“独立来源数”的替代

| Qwen 判据 | 问题 | 替代判据 |
|---|---|---|
| 独立租户数 ≥ 2 自动共享 | 攻击者可制造多租户；热门机密会误共享 | 有可审计的公共/授权来源 |
| 观察期持续访问 | 热度不等于公共性 | 发布/ACL 事件驱动 |
| 跨会话重复 | 同租户其他用户可能在探测 | 按用户/会话作用域复用 |
| 全局共享状态 | 成员关系仍泄露 | 公共/授权池原子块 + 作用域查询 |

---

## 7. 发布时预热：切断“某用户首次使用”这一信号

如果共享内容仍由“第一个用户请求”触发缓存填充，攻击者可能从命中时间推断：

> “这份共享文档最近是否被某个用户首次访问过。”

因此，G/A 池建议：

1. 公共内容在发布/更新时由后台预计算；
2. A 池文档在获得 ACL/项目授权时预计算；
3. 热点内容按调度预取，而不是仅靠请求触发；
4. 无法预热的长尾内容，保留在 P 池或按授权池按需生成，不暴露给未授权用户；
5. 共享池容量采用单独配额，避免请求高峰的驱逐行为形成活动信号。

预热不增加正常用户延迟，反而降低首次命中延迟。

---

## 8. 观测去相关：别让侧信道从接口重新长出来

即使池隔离正确，对外仍需避免以下暴露：

| 暴露点 | 风险 | 处理 |
|---|---|---|
| 响应头 `cache_hit`、`hit_tokens` | 直接返回命中状态 | 不返回或仅内部可见 |
| 响应返回 AIOF/缓存节点地址 | 节点变化暴露命中/未命中 | 对客户只返回稳定入口 |
| 命中 Token 折扣计费 | 账单泄露命中 | 对外按逻辑 Token 统一计价 |
| 细粒度缓存指标 | 可观测他人缓存活动 | 按服务等级/时间窗聚合 |
| 不同未命中/无权限错误 | 存在性预言机 | 统一错误语义 |
| 命中请求进入快速 Batch | 调度行为暴露 | 不将命中状态作为对外调度信号 |

注意：这里不是要让所有请求时间相同，而是**未授权请求不会触发受害者池查询**。对已授权用户，命中带来的低延迟可以保留。

---

## 9. 攻击场景重放

### 9.1 跨租户私有 RAG 文档

```text
受害者：租户 A 的私有文档 → P 池（用户/部门作用域）
攻击者：租户 B
攻击者查询：公共 G 池 + 自己的 P 池 + 自己获授权的 A 池
```

受害者 P 池不进入攻击者查询空间。攻击者逐 Token 猜测，只会观察到自己在 P 池中的状态，无法得到受害者字Token是否正确。

### 9.2 同租户不同用户

```text
用户甲私有文档/对话 → P 池（用户甲）
用户乙查询 → P 池（用户乙）
```

不再采用“租户级共享池”来承载普通用户请求；只有企业明确发布的共享资产进入 A 池。

### 9.3 授权项目文档

```text
项目 P 的成员 → A 池（项目成员集合）
项目外攻击者 → 无 A 池查询权限
```

授权成员可以复用项目文档；项目外用户无法探测其存在。

### 9.4 同一用户跨会话

```text
用户甲的历史文档 → P 池（用户甲级）
用户甲的新会话 → 可复用
```

跨会话体验保留，但其他用户不可见。

### 9.5 攻击者知道完整私有块，测试成员关系

```text
私有块 → 不进入 G/A 池
攻击者无授权 → 不查询受害者池
```

攻击者无法通过全局目录获得“该块是否存在”的反馈。若攻击者本身是授权成员，则成员关系属于授权集合内信息，需通过发布时光预热/生命周期驻留进一步限制活动痕迹。

### 9.6 攻击者对公共 System Prompt 高频探测

G 池是公共内容，命中公共内容本身不泄露其他租户私有前缀。高频滥用交给通用限流/配额，不应通过拖慢正常公共请求解决。

---

## 10. 用户体验与“不依赖用户配合”

### 10.1 用户体验

| 路径 | 行为 |
|---|---|
| 公共 G 池命中 | 直接复用，无新增等待 |
| 授权 A 池命中 | 直接复用 |
| 个人 P 池命中 | 直接复用 |
| 未命中 | 正常 Prefill，不增加延迟 |
| 跨站命中 | 按原有路由/经济性逻辑 |
| 未授权请求 | 正常计算，不访问受害者池 |

本方案不采用：

- 固定延迟；
- 命中后重算；
- 慢速 Batch 惩罚；
- 返回伪造结果；
- 随机抖动。

### 10.2 不依赖用户配合

- 用户无需声明隐私等级；
- 用户无需改变 API；
- 系统从身份、ACL、部署清单、RAG 来源自动推导；
- 未识别来源默认私有；
- 公共性由平台/内容方/管理员登记，而不是让普通用户打标签。

### 10.3 必须接受的收益取舍

无授权关系的两个租户，即使输入了同一段私有文本，也不应共享缓存。

这与“任意私有内容全量全局复用”相比会损失一小部分命中，但：

- 公共系统提示与工具前缀的复用仍在；
- 授权项目/共享文档的跨租户复用仍在；
- 同一用户跨会话复用仍在；
- 安全可复用的主体收益被保留。

如果业务确实存在跨租户私有复用需求，应通过**显式授权组/共享项目**建立 A 池，而不是依赖热度推断。

## 11. 与 Qwen 方案逐项对照

| 主题 | Qwen | 本报告建议 |
|---|---|---|
| 全局池准入 | 独立来源数/热度自动晋升 | 公共来源证明 + ACL 授权 + 默认私有 |
| 私有内容 | 多会话/多租户重复可晋升 | 用户/会话私有，不因重复自动共享 |
| 匹配粒度 | 固定 256/512 Token 块 | 内容定义原子块，只用于 G/A 池；P 池 Token 级 |
| 块内匹配 | 完整块才命中 | 保留，并禁止共享池回退 Token 匹配 |
| 同租户用户 | 可能进入租户私有共享 | 默认用户级；只有发布资产进入授权池 |
| 攻击检测 | 区域蜜罐 + 背景 Batch 拖慢 | 仅作滥用治理；不作为隐私主防线 |
| 攻击者响应 | 被拖慢到 Miss | 不返回伪造结果，不拖慢合法用户 |
| 计费/指标 | 未展开 | 必须去相关 |
| 复用率承诺 | ≥95%、零延迟、零算力 | 改为可实测的“安全可复用覆盖率” |
| 安全结论 | “彻底切断” | 明确残余风险与边界 |

## 12. 残余风险与边界

### 12.1 授权集合内的活动痕迹

同一 A 池内所有成员都有权访问文档，但共享缓存冷热可能暴露“最近有没有人访问过”。

可选措施：

- 发布/授权时预热并保持生命周期驻留；
- 按对象更新节奏刷新，不由单请求决定；
- 对活动痕迹极敏感的内容，收窄到用户级 P 池。

### 12.2 攻击者已经知道整个块

原子块可以防止逐 Token 恢复，但不能阻止“知道完整块后测试其是否存在”。因此：

- 私有块不进入可被无权限请求者查询的池；
- 授权池的成员关系仅对授权集合可见；
- 目录索引使用作用域密钥，防止目录泄密后离线枚举。

### 12.3 误标为公共的内容

如果管理员/内容方错误地把私有内容登记为 G 池，任何方案都无法补救。需要：

- 公共登记审计；
- 双人审批或签名；
- 撤回与全局删除；
- 公共资产变更审计。

### 12.4 平台内部与物理侧信道

缓存管理员、节点被攻破、功耗、电磁等不在本方案范围，需要 TEE、密钥封装、节点可信和平台安全配合。

### 12.5 合法批量相似请求

不再用“微小变异”直接惩罚用户。批量改写、A/B 测试、模板生成可通过正常配额和业务白名单处理，避免把合法用户当成攻击者。

---

## 13. 落地顺序

### 阶段 0：先做最小可行隔离

1. 请求身份和会话作用域进入缓存键；
2. 私有 Prompt 默认进入 P 池，不做跨用户共享；
3. 公共模板进入 G 池；
4. 移除对外命中标识、节点地址、命中 Token 计费和细粒度缓存指标。

### 阶段 1：建立 G/A/P 三池

1. G 池接入公共资产登记；
2. A 池接入 RAG ACL、项目成员、部署清单；
3. A 池支持跨用户、跨租户、跨站点；
4. 实现前缀血缘：私有后缀继承最严格作用域；
5. 授权变化时失效旧能力凭证。

### 阶段 2：启用原子块

1. 对 G/A 池启用完整原子块匹配；
2. 共享池禁止 Token 级回退；
3. 使用内容定义分块，按工作负载校准最小块长；
4. 对最后不完整块保留在 P 池；
5. 对公共/共享资产后台预热。

### 阶段 3：旁路治理与评估

1. 稳定接入地址和内部缓存路由；
2. 计费与指标去相关；
3. 公共/授权池容量配额，减少驱逐侧信道；
4. 异常检测只用于资源滥用和配额，不承担隐私主防线；
5. 红队测试跨租户、同租户跨用户、跨会话、目录泄露、Sybil 晋升、块边界攻击。

---

## 14. 验证指标

### 14.1 安全指标

- **跨租户/跨用户 Hit/Miss 区分优势**：在攻击者无受害者池权限时，受害者条目存在/不存在两种状态下，攻击者观测分布差异应接近随机；
- **逐 Token 恢复成功率**：给定攻击预算，统计能否恢复私有 Token；
- **块成员探测**：攻击者知道完整块时，能否在无授权池查询到存在性；
- **目录泄露测试**：获得目录数据后能否枚举私有块；
- **Sybil 晋升测试**：攻击者创建多个租户/会话是否能使私有内容进入 G 池。

### 14.2 复用指标

- G 池公共内容的跨站点命中率；
- A 池授权共享内容的跨用户/租户命中率；
- P 池同一用户跨会话命中率；
- 原子块带来的额外 Prefill（相较 Token 级缓存）；
- 安全可复用覆盖率：实际复用 ÷ 在相同授权集合下理论可复用量。

### 14.3 体验指标

- G/A/P 各路径的 P50/P99 TTFT；
- 跨站拉取与预热成本；
- 权限校验和目录查询开销；
- 未命中路径与基线对比，确认没有人为延迟。

---

## 15. 最终建议

### 15.1 对 Qwen 方案的处理

- **保留**：块级匹配思想；
- **升级**：改为内容定义原子块，只用于 G/A 池，禁止 Token 级回退；
- **替换**：独立来源/热度晋升 → 来源证明 + ACL 授权 + 默认私有；
- **降级**：区域蜜罐/背景 Batch → 仅作滥用治理；
- **补充**：发布时预热、三池可见性、响应/计费/指标去相关；
- **修正**：删除“≥95%”“零延迟”“彻底切断”等不可复核承诺，改为可测目标。

### 15.2 一句话方案

> **公共内容进入全局原子块池，授权共享内容进入 ACL 作用域池，私有交互只进入用户/会话池；请求只查询自己可见的池，共享池只接受完整原子块命中；共享内容由发布事件预热，而不是由用户请求驱动；所有外部接口不暴露命中状态。**

### 15.3 这样做是否满足三个要求

- **保持全局可复用优势**：公共内容、授权共享内容、同一用户跨会话内容继续复用；只损失无授权私有内容的重复复用；
- **保持正常体验**：不增加延迟、不重算已有 KV、不伪造输出；私有用户缓存仍可使用 Token 级前缀加速；
- **不依赖用户配合**：从身份、ACL、部署清单、RAG 来源自动决定作用域；未知内容默认私有。

---

## 16. 后续可继续深化的方向

1. **内容定义原子块的参数与实现**：最小块长、边界算法、最后块处理、跨模型兼容性；
2. **前缀血缘算法**：RAG 文档、工具返回、对话历史的来源传播与作用域求交；
3. **G/A 池的跨站点复制策略**：公共无限复制、授权内容按站点成员复制、私有内容加密迁移；
4. **授权撤销与缓存失效**：策略版本、旧条目隔离、后台删除；
5. **红队评测**：跨租户逐 Token、同租户跨用户、完整块成员测试、目录泄露、Sybil 晋升、低慢速攻击；
6. **是否能进一步安全地支持“跨租户私有合作”**：只能通过显式共享项目/授权组，不建议通过统计热度推断。

> 核心判断不变：**要同时保住体验和大部分复用，必须让未授权请求根本进入不了受害者缓存池；块级匹配是用来兜底“误入共享池”场景的第二道防线，而不是第一道防线。**
