# 跨站点、跨租户/用户、跨会话 KV Cache 全局复用侧信道防护解决方案（最终完整增强版）

**方案名称**：基于三级作用域隔离与带锚点承诺原子块匹配的抗侧信道 KV 缓存复用系统（TPC-ABM-Enhanced）

**文档日期**：2026-11-11

## 0. 执行摘要

### 0.1 方案一句话

> 将全局 KV Cache 拆为公共 G 池、授权共享 A 池和用户/会话私有 P 池；请求只查询自身可见的池；G/A 池只接受带有父块锚点承诺的完整原子块命中，P 池保留 Token 级前缀复用；共享内容由发布/授权事件预热，未知来源默认私有；引入控制面凭证预计算与分池动态配额，在不增加人工延迟、不重算 KV 的前提下，彻底切断时序侧信道盲打。

### 0.2 本方案解决的攻击

在跨站点、跨租户/用户、跨会话复用 KV Cache 时，攻击者可以通过逐 Token 构造候选前缀并测量命中/未命中时延，逐步恢复他人的私有前缀、RAG 文档、System Prompt 或对话历史。

攻击成立依赖于攻击者可控构造候选前缀、进入同一缓存匹配空間、系统提供 Token 级细粒度命中反馈等条件。本方案直接切断其中最有效的两个环节：

1. **共享性**：私有内容不进入攻击者可查询的池。

2. **细粒度反馈**：对外共享池只处理完整原子块，不提供 Token 级命中信号。

本方案**不采用**：人工注入延迟、命中后重新完整 Prefill、随机延迟/噪声、返回伪造数据、仅依赖异常检测等。

## 1. 问题与威胁模型

### 1.1 需要保护的资产

1. 其他用户/租户的私有 Prompt 前缀；

2. 私有 RAG 文档、System Prompt、工具返回结果；

3. 对话历史与会话上下文；

4. “某文档/某前缀存在”或“某用户使用过某主题”的成员关系事实；

5. 共享内容的访问活动痕迹。

### 1.2 攻击者

- **跨租户攻击者**：可调用推理 API，构造候选前缀探测其他租户内容。

- **同租户其他用户**：与受害者同一企业，但不属于同一用户/部门/项目。

- **分布式探测群**：多个账号/会话低慢速探测，规避单账号限流。

## 2. 总体架构：三池结构与增强设计

### 2.1 三池逻辑隔离（物理共享、逻辑隔离）

- **G 池（公共原子块池，Global Atomic Pool）**：只接收有可审计公共来源的内容，跨站点、跨租户、跨会话复用，只接受完整原子块匹配。

- **A 池（授权共享池，Audience Pool）**：只接收有 ACL/项目/部署授权的内容，在授权主体集合内跨用户、跨租户、跨站点复用，只接受完整原子块匹配。

- **P 池（私有池，Principal/Session Pool）**：接收用户输入、对话历史、个人上下文，支持 Token 级前缀缓存，只在同一最终用户或同一会话内可见。

### 2.2 增强机制：凭证预计算与动态配额

- **凭证预计算（CacheViewTicket）**：静态资产和项目级 ACL 权限血缘在会话建立时预计算并固化，请求到达时仅做内存级凭证有效性与策略版本（`policy_epoch`）校验，消除实时解析延迟。

- **分池动态配额（Tiered Quota）**：物理缓存层为 G、A、P 三池设定动态显存配额比例，并引入跨池冷热置换保护，防止私有洪峰挤压公共资产缓存。

## 3. 核心机制：带锚点承诺的原子块匹配（Parent-Committed Atomic Blocks）

### 3.1 内容定义分块（CDC，无需用户介入）

- **自动边界定义**：系统对规范化的 Token 序列进行内容定义分块（CDC），通过滚动哈希（Rolling Hash）自动确定块边界，最小块长 $B_{\text{min}}$ 可配置。该过程完全由系统自动化完成，**不需要普通用户介入、填写隐私等级或逐请求传递标签**。

- **锚点承诺优化**：块键计算引入父块承诺（`parent_commitment`），确保即使攻击者猜对了某中间段落，由于缺乏正确的上下文父块链条，也无法将其拼接到全局缓存目录中。

- 计算公式：

  $$\text{BlockKey} = \text{HMAC}\left(\text{ScopeKey}, \, \text{model\_manifest} \parallel \text{block\_tokens} \parallel \text{parent\_commitment}\right)$$

### 3.2 完整块约束

- G/A 池查询：**完整块命中**允许复用；半块、块内部分前缀一律不允许命中，禁止回退到 Token 级全局匹配。

## 4. 来源解析与可见范围判定

### 4.1 自动血缘推导与有效作用域交集

- 复用范围和权限由系统根据现有的**身份、ACL、项目、部署清单和内容来源自动确定**；无法识别的内容默认归属当前用户或会话，按最小可见范围（P 池）私有处理。

- 每个来源具有独立作用域（Public、Audience、Principal、Session），任意前缀的有效作用域为其所有上游来源作用域的最严格交集：

  $$\text{EffectiveScope(prefix)} = \bigcap \text{EffectiveScope(source}_i\text{)}$$

### 4.2 核心规则

> 共享文档可以复用，但用户私有后缀不能通过“挂靠”共享文档进入 A 池或 G 池。包含用户私有交互之后生成的 KV，其作用域自动收窄为当前用户。

## 5. 外部旁路治理与外部特征

### 5.1 方案的外部旁路治理

1. **无显式缓存标识**：对外接口的响应中不包含任何诸如 `cache_hit`、`hit_tokens` 或 `X-Cache-Node` 等调试或缓存状态指标。

2. **错误与状态盲化**：对无权访问、资源不存在、未命中的请求，采用统一结构和相近时延的响应，消除存在性预言机。

3. **计费与调度解耦**：对外统一按逻辑输入 Token 计价，缓存节省仅在内部体现；不将命中状态作为对外 Batch 调度优先级的直接依据。

### 5.2 系统在外部表现出的黑盒特征

- **响应时延的“量子化跳跃”**：在未凑齐完整的原子块前保持未命中时延，一旦凑齐完整原子块，TTFT 呈非连续的块级突变式下降。

- **错误响应盲化统一**：越权查询不返回细粒度差异化报错，对外表现一致。

- **跨会话加速持久性**：同一认证用户跨会话享有稳定的加速，切换不同用户账号后无法继承前者的缓存加速。

## 6. 专利侵权举证与验证方法

为了证明竞争对手或相关系统是否侵害本专利，可采取以下维权与取证手段：

1. **行为学探测与时序分析（Probing & Timing）**：通过自动化脚本发送阶梯递增前缀，统计 TTFT 分布。若表现出块级突变（Atomic Block alignment）而非 Token 级平滑渐变，且对越权查询表现出时序盲化，可证明其采用了类似原子块匹配与作用域隔离逻辑。

2. **供应链与组件审计（Source Code / Component Audit）**：检查其开源代码、白皮书或容器镜像，若发现实现了 `pool_type`（分池）、`effective_scope`（血缘交集）、`policy_epoch` 或内容定义分块（CDC）带锚点承诺的类/函数，可作为直接侵权证据。

3. **流量抓包分析（Network Telemetry）**：分析分布式节点间在跨站点拉取 KV Cache 时，是否传递了带有作用域凭证或策略版本的控制面信令。

## 7. 总结

> **公共内容进 G 池，授权内容进 A 池，私有交互进 P 池；请求只查可见池，共享池只认带锚点承诺的完整原子块；系统自动CDC分块与血缘推导，无需用户介入；命中状态不出接口；未授权内容根本不进入查询路径。**
