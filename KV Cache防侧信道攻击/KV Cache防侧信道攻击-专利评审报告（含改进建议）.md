# 第一部分　专利审核人评审意见

## 1. 对母方案与问题的理解（评审基线）

### 1.1 母方案在做什么

V3 构想把 LLM 推理的 KV Cache 从"引擎内一次性私有内存"升级为"**内容寻址、可跨节点跨地域复用的资产**"，以"全局网关① + KV 目录② + 中心 Prefill DC⑤ + 区域 POP⑥ + 边缘 Decode⑦ + WAN 加速层⑨"承载，核心三支柱：

1. **调度范式逆转**：请求找数据（亲和路由 `RouteQuery/RouteGrant`），而非数据找请求；
2. **生产—分发—消费管线**：上下文按共享度拆 A/B/C/D 模块，中心生产、指纹上报、低谷异步预分发、边缘就近消费；
3. **经济博弈 + 全局降级**：每次跨域先算 `T_fetch vs T_local vs T_center`，边缘不满足 SLA 则中心接管。

### 1.2 母方案引入的新问题（本专利的立足点）

一旦 KV 全局共享，**Hit/Miss 的时延差即成为跨租户窃密信道**：

- Hit（本地显存读取）≈ 10–100 ms；Miss（跨节点拉取 / 重算）≈ 数百 ms–5000 ms 以上；
- 攻击者逐 Token 微调 Prompt + 高精度测 TTFT，即可像"盲打"一样逐字节恢复他人私有前缀（私有 System Prompt、企业 RAG 机密、对话历史）。

该问题真实、有据，且是企业落地的**硬门槛**（V3 §7.3 已将其列为开放问题第 4 项）。以此为专利立足点，成立。

### 1.3 标准侧的客观空白（可复核）

- TR 23.801-01 §6.19.4 定义了 **AIMF（管理）/ AIOF（执行）/ AIRF（仓库）/ AISF（导引，含 "AI context correlation and caching management"）**，但全文未出现 KV cache 侧信道；
- §6.22（KI#22）的 SHE、CCF/CMF 及"有状态计算上下文缓存 + 先建迁移链路"几乎是 KV 跨站迁移的标准语言，同样无安全约束；
- TR 33.801-01 现有 KI 全部围绕认证/授权/机密性/完整性/重放，**无任何推理时序侧信道、跨消费者上下文泄露的关键问题**。

**评审认定**：空白客观存在，且 Rel-20 研究期（架构选项与功能划分大量 FFS）是把方案写入 `Solution/Interim Agreement` 的最佳窗口；进入 Rel-21 规范阶段后门槛显著提高。

## 2. 现有技术检索与最接近现有技术（区别点预审）

> 说明：以下为预审方向，**正式申请前须由专利代理人做穷尽式检索**。

| 现有技术 | 技术路线 | 与本构思的关系 |
|---|---|---|
| vLLM PagedAttention / SGLang RadixAttention | 单集群跨请求前缀复用 | 未跨域、无安全机制，背景技术 |
| Mooncake / MemServe / Preble | 集群级 KV 池化、缓存感知调度 | 假设可信高速 LAN；**缓存感知调度本身正是泄露源（C4）** |
| PrfaaS / `An Internet for the KV Cache` | 跨 DC Prefill 卸载、纲领性互联 | 无多租户侧信道防护 |
| **SafeKV（arXiv 2508.08438，2025）** | **Selective KV-Cache Sharing to Mitigate Timing Side-Channels** | ⚠️ **最接近现有技术**：已在单引擎内按策略选择性共享 |
| NDSS 2025 "I Know What You Asked"（PROMPTPEEK 类） | KV 共享提示泄露的攻击实证 | 攻击侧证据，非防御 |
| 密码学恒定时间 / 填充（constant-time、padding） | 通用侧信道缓解 | **通用手段，单独使用无创造性** |
| 通用多租户密钥/命名空间隔离（KMS、per-tenant key） | 通用云隔离 | **通用手段**，创造性须落在"与推理上下文内容寻址、运营商签约/策略裁决、释放时刻对齐"的特定结合 |

**关键评审判断（创造性落点）**：

- 单独的"加延迟填充""按租户发密钥""蜜罐"都是**已知通用手段**，不具备创造性；
- SafeKV 已在**单个推理引擎**内做"选择性共享"。本专利若权利要求停留在"按敏感度选择是否共享 KV"，**极可能被 SafeKV 否决**；
- 真正可能建立创造性与标准必要性的，是以下**特定组合与架构层级特征**（SafeKV 与通用 KMS 均不具备）：
  1. **网络级（运营商）裁决**：复用域由 AIMF 依据 **UDM 签约上限 + PCF 策略 + AF/UE 声明**在会话建立时裁决，跨多个 SHE 计算站点生效；
  2. **签约绑定的域密钥注入内容寻址索引**（`H(K_domain ‖ model_id ‖ prefix)`），实现跨域"相同前缀也不可命中"；
  3. **选择结果对消费者隐藏**（只暴露 AISF 锚点，不暴露 AIOF 地址）；
  4. **释放时刻量化（Release Quantum）以 QoS 参数下发执行**；
  5. **指标暴露 / 选择 / 计费的去相关**（对齐报告 C2–C5）；
  6. 上述机制全部以**可被抓包/接口观测的信令行为**外显（SEP 可检测性）。

> 这是一条"**单引擎做不到、必须靠网络协同**"的创新线，应作为本专利的主轴。

## 3. 实质性缺陷评审（决定能否授权 / 保护是否成立）

### 缺陷 1【严重 · 安全归因错误】雪崩哈希不是防护来源

**现稿主张**：用"语义哈希 + SHA-256 强雪崩"生成 Salt，微调 1 Token 即 Salt 剧变，"破坏前缀→时间映射梯度"，令逐 Token 探测失效。

**评审认定：该安全逻辑不成立。**

1. 前缀探测**不依赖"梯度"**。攻击者每次提交的是**完整候选前缀**（已恢复部分 + 下一候选 Token），不是只发增量；
2. 雪崩效应只保证"**不同**输入的哈希相互独立"，**不阻止"相同输入精确匹配"**。攻击者构造的候选前缀若与受害者完全一致，哈希/盐完全一致，命中照样发生；
3. 若 Salt 对所有租户**相同或可推导**（现稿正是全局 SHA-256(P)），则 Salt 是公开函数，攻击者可自行计算，**盲化等于没有盲化**。

**正确归因**：防护只能来自**按复用域分配的秘密密钥 K_domain 带来的命名空间隔离**——攻击者不在域内、不知 K_domain，即便构造出完全相同的前缀也查不到对方块。SHA-256 可作为索引构造的哈希构件，但**不是创造性、也不是安全来源**。

> 对申请的影响：若按现稿把"雪崩哈希破坏梯度"写为发明点，既会在审查中被通用哈希/无安全贡献驳回，也会导致实际产品**防不住攻击**（方案与效果不符）。必须改。

### 缺陷 2【严重 · 保护边界与结论不符】对齐到 ~100ms 隐藏不了 Hit/Miss

**现稿主张**：把 Hit 对齐到"跨节点拉取时间 ~100ms"而非重算 5000ms，体验无损且"攻击彻底失效"。

**评审认定：以偏概全，结论不成立。**

1. 对齐到 100ms 只抹平了"**本地 Hit（10ms）vs 远端 Hit（100ms）**"，即只隐藏**位置/层级**；
2. "有缓存（100ms）vs 真未命中（5000ms）"仍相差约 50 倍，**单次测量即可区分**，Hit/Miss 信道仍在；
3. 因此"攻击彻底失效""30 天无法 80% 区分"与该机制的实际能力**自相矛盾**。

**正确表述**：该机制的保护目标应严格限定为"**隐藏缓存层级/位置与站点负载信息**"；对 L1–L3 私有内容的保护**依赖缺陷 1 所述域隔离**（跨域不可命中，自然不存在需要对齐到 5000ms 的问题）。"彻底""完美"等措辞须全部改为 "mitigate / bound the leakage（缓解 / 界定泄露）"。

### 缺陷 3【严重 · 合规与责任】静默返回伪造数据不可原样提交

**现稿主张**：识别攻击后"不封禁、不告警"，静默路由到蜜罐推理实例，返回伪造延迟和假 Token，让攻击者收集假数据。

**评审认定：与 3GPP 原则和法律责任冲突，风险高。**

1. 3GPP 对网络 AI 推理要求**保障 KPI（含精度）**（§6.19.4 原则 29、PR 6.10.6-3），并在 TR 22.870 §6.39 讨论负责任/可信 AI —— 网络有意返回错误结果与此冲突；
2. **检测必有误报**。被误判的合法用户（A/B 测试、批量改写 Prompt 的开发者、自动化办公流）将收到错误结果，可能引发安全事故与赔偿责任；
3. **合法监听/监管**场景下网络篡改用户可见内容难以辩护；
4. SA3 响应框架（KI#7.3）允许"**重定向**恶意流量"，但**没有"欺骗"语义**。

**正确做法**：改为"**重绑定至无跨租户复用的隔离实例（结果真实，仅失去共享收益、性能略降）+ 在其可见缓存中放置诱饵前缀（canary）**"。诱饵若被命中探测，即获得**高置信攻击证据**，再按策略限速/撤权/通知 AF。这同样静默、同样令攻击者一无所获，但**不伤害被误判用户**，且完全落在 KI#7.3 的"重定向"语义内。

> 注：真正面向"已确认恶意身份"的高交互蜜罐（明确标注为威胁情报、不服务任何真实业务）可作为**可选防御性实施例**，但不得作为对正常签约流量的默认动作。

## 4. 威胁模型完整性评审（现稿遗漏）

现稿威胁模型基本只覆盖"跨租户 TTFT 主信道（C1）"。评审认定存在三类遗漏：

### 4.1 遗漏一：域内攻击者（域隔离的"最后一公里"）

域密钥按租户隔离后，能挡跨租户；但**同一租户内部**仍非铁板一块：

- 一个低权限员工/被攻破的部门账号，可以探测**本租户其他部门、其他员工**查询过什么（C 模块"租户内共享"、D 模块"会话"边界如何划分？）；
- 攻击者只要是该域合法成员、持有 K_domain，Hit/Miss 信道对其**重新开放**。

**要求**：复用域必须支持**层级化**（如 `Global / Tenant / Department / User / Session`），C 按部门或用户群、D 按会话分别分密钥，而非一把租户钥匙开全租户。

### 4.2 遗漏二："存在性预言机"与元数据隐私

泄露的不只是内容，还有"**某前缀/某文档存在或被查询过**"这一事实本身：

- 攻击者可探测"租户知识库中是否存在代号 `Project-X` 的文档""某人是否查询过 M&A 相关材料"；
- 即使读不到内容，**存在性**即可推断并购、裁员、重组等敏感事件。

该问题在域内（4.1）与 L1 半公共层尤其突出。**要求**：威胁模型须把"存在性/成员关系（membership）"单列为资产，并说明默认私有、白名单提升、释放对齐与诱饵如何共同限制存在性判定。

### 4.3 遗漏三：标准自身引入的 C2–C5 泄露面

对齐报告已指出，3GPP 在研方案自身会"开后门"，而学界与现稿只讨论 C1：

| 信道 | 机理 | 标准来源 |
|---|---|---|
| C2 网络辅助测量 | 用暴露的 N3/N9/N6、E2E 时延减去网络时延，得到更纯的计算时间 | Solution #22.10；QoS 监测 |
| C3 计算指标暴露 | TTFT、ms/token、"负载→处理时间映射"直接可读缓存状态 | Solution #22.9 Variant B；#19.4 Mechanism 2 |
| C4 选择结果泄露 | 授权后回传的 **AIOF 地址/DNAI** 随命中而变 | §6.19.4.1.1.3；Solution #22.2 |
| C5 计费/用量泄露 | Hit 折扣计费 / "消耗 token"上报 → 账单泄露命中 | 资源用量上报；PR 6.14 |

**评审认定**：指出并约束 C2–C5 是本专利相对纯学术方案**最有说服力的差异化价值**，也是 SEP 布局的富矿，**必须纳入独立方案或专设"暴露与计费去相关"子层**。

## 5. 核心承重机制成熟度评审：域密钥"欠规约"

整改后，**域密钥是整个防御的承重墙**，但现稿（含对齐报告）对其工程规约不足，评审要求补齐以下四点（同时这四点本身是很好的从属专利点）：

1. **密钥分发与 AIOF 驻留安全**：AIOF/AISF 需持有大量租户/部门密钥 → 它本身成为高价值目标。须规定密钥以 **HSM/TEE 内包装密钥（envelope/wrapping）**下发、索引计算在受保护环境进行，AIOF 被攻破不暴露全部租户；
2. **密钥轮换与"重算风暴"**：轮换 K_domain 会使该域**所有已缓存块不可寻址**，强制大规模重算。须规定**不失效块的重密钥机制**（见第三部分 §建议 6：惰性重封装 + 后台迁移），把"轮换"与"重算"解耦；
3. **密钥生命周期与签约/许可耦合**：签约撤销、订户许可撤回 → 域密钥销毁/轮换 → 旧块不可寻址并按留存策略回收（借 KI#21"许可撤回即删"原则）；
4. **跨域/跨站迁移约束**：上下文迁移链路只在同复用域内建立，跨域须重新派生、重新加密。

> 若不规约以上四点，"域隔离"在生产中要么不敢轮换（长期密钥风险），要么一换就重算风暴（性能风险），承重机制不可用。

### 5.1 对"方式 b 直连"的额外泄露评审

母方案默认客户端在 `RouteGrant` 后**直连**边缘节点。释放时刻对齐若只在 AIOF 执行，覆盖不到：

- **`RouteQuery→RouteGrant` 自身耗时**可能反映目录命中数/查找复杂度；
- **到不同 Endpoint 的 TCP/TLS 握手与网络 RTT 差异**在任何业务字节之前就泄露节点身份与位置；
- **授权失败 vs 未命中**的失败路径时延可能不同。

须在**网关侧也做归一化**（对授权失败/未命中返回同构响应与同构时延；对外只给 AISF 锚点），不能只对齐 AIOF。

## 6. 定量主张可复核性评审

现稿三大主张均**无测量方法、无负载定义、无攻击者预算**：

| 主张 | 问题 |
|---|---|
| 复用率 ≥ 95% | "复用率"未定义；L0 复用高度依赖业务的跨租户前缀重叠度，可能远低于 95% |
| TTFT 增加 ≤ 5% | 文献（SafeKV 引述）按用户隔离使 TTFT 增加约 **2.3%–38.9%**（视模型与重叠度），区间很宽 |
| 30 天无法以 >80% 置信区分 | 未规定攻击者查询预算、采样方式、统计检验 |

**评审要求**：

1. 定义**工作负载**（跨租户前缀重叠度分布、A/B/C/D 占比、长上下文比例）；
2. 定义**攻击者模型**（A1 已签约 UE 恶意应用 / A2 被攻破 AF / A3 分布式慢速群）与**查询预算 Q**；
3. 采用**形式化泄露指标**：
   - **区分优势** `Adv = |Pr[A→HIT] − Pr[A→MISS]|`，要求 `Adv ≤ ε`（在预算 Q 下）；
   - 统计检验用 **KS 检验**等，给出分布重叠度；
4. "复用率"定义为 **L0 可复用 token 占比**，而非全体；
5. 文中一律以"**示例/目标值（target）**"表述，不写成承诺值。

1. **单一性风险**：现稿五层（分级 / 盲化 / 时序对齐 / 蜜罐 / 影子计算）彼此可独立存在、解决不同子问题。若捆进一个独立权项，可能因**缺乏单一发明构思**被要求分案，且任一层命中现有技术都会拖累主权项；

4. **抽象对象中立**：进标准/主权项用"**可复用 AI 推理上下文（Reusable AI Inference Context, RAIC）**"，NOTE 中举例 "e.g. KV cache of transformer-based models"，避免被认定为应用层实现而落入 3GPP 不管辖范围。

# 第二部分　专利提出人改进建议

> 以下是我作为**提出人**，针对第一部分评审意见给出的整改方案。建议据此重写交底书并规划专利族。

## 建议 0：重写发明的一句话定位

> **发明名称（建议）**：一种跨计算站点的可复用 AI 推理上下文的运营商可控复用与时序侧信道防护方法、系统及装置。
>
> **标准定位（英文，可作提案标题）**：
> *"Support of secure, operator-controlled reuse of AI inference context (e.g. KV cache) across Computing Sites for network AI inference service, with protection against inference-context timing side channels."*

## 建议 1：重构威胁模型（补齐 A1–A3 + 域内 + 存在性 + 预算）

- **资产**：他人提示前缀内容；**以及"某前缀/文档存在或被使用过"的成员关系事实**；
- **攻击者**：A1 已签约 UE 恶意应用；A2 经 NEF 的（被攻破）AF，可订阅指标；A3 分布式慢速探测群；**新增 A4：同租户内低权限/被攻破账号（域内攻击者）**；
- **信道**：C1 TTFT + C2 网络辅助 + C3 指标暴露 + C4 选择结果 + C5 计费；**新增 C6：网关查询时延与握手/直连路径差异**；
- **不在范围**：SHE 内特权/物理侧信道（功耗、电磁）——归平台/TEE；
- **查询预算 Q**：显式给出攻击者在时间窗 T 内的最大请求次数，所有泄露结论都相对 (T, Q) 表述。

## 建议 2：默认私有（private-by-default）+ 层级复用域

- 新生 KV 块**默认按最小域（会话/用户）私有入库**，后台自动评估，仅在策略允许且达抗操纵阈值时提升；
- 复用域层级：`Global(L0公共) / Tenant / Department(或用户群) / User / Session`，分别对应 A/B/C/D：
  - **A 全局 System Prompt、B 标准 Tool Schema** → Global/业务线域，可跨租户；
  - **C 租户 RAG** → Tenant/Department 域；
  - **D 对话历史** → Session/User 域；
- 签约新增上限属性 **`AllowedContextReuseScope ∈ {None, Session, User, Tenant, Global}`**（UDM），策略由 PCF 下发 **Context Reuse Policy**（默认等级、L0 白名单、升降级规则、保留期）；
- **抗"投毒式提升"**：提升到跨租户域须满足"**不同签约主体数 ≥ N 且来源/时间多样性**"，攻击者无法靠制造共享度诱导升级。

## 建议 3：域密钥注入内容寻址索引（核心权项）

- 上下文索引键：`idx = H(K_domain ‖ model_id ‖ compatibility_manifest ‖ token_prefix)`；
  - `K_domain` 由 AIMF 在会话建立时按裁决的 Reuse Domain ID 派生（可沿 **AKMA/签约绑定密钥**思路），下发 AISF/AIOF；
  - L0 公共域用全网公共密钥；L1–L3 用租户/部门/会话密钥；
- **查找顺序**：L0 先查公共域，再查本域；跨域相同前缀**不可命中**；
- 密钥在 AIOF/AISF 以**包装密钥 + HSM/TEE** 驻留，索引计算受保护；
- **明确写入交底书**：哈希雪崩**不是**安全来源，安全来源是 K_domain 的秘密性与域隔离；SHA-256 仅作索引构造构件（从属权项）。

## 建议 4：释放时刻量化 + 网关侧归一化（有界对齐）

- AIMF 为会话下发 **`Target First-Result Latency` 与 `Release Quantum`**（如 50 ms 桶），AIOF/AISF（或 xUPF 业务特定功能）将首结果释放时刻对齐到量化桶，使"本地命中 / 远端命中 / 同站热迁移"不可区分；
- **保护边界如实写明**：该机制隐藏的是**层级/位置/负载**，不单独承诺隐藏 hit/miss；私有内容靠域隔离；
- **网关侧归一化（补 C6）**：`RouteQuery→RouteGrant` 时延、授权失败/未命中响应、对消费者回传的地址全部同构；L1+ 只返回 **AISF 锚点**，AIOF 切换在 AISF 之后完成；
- L3（金融/医疗）以策略标志 **`Constant-Latency Execution Required`** 触发恒定执行 AIOF（影子计算/TEE/固定批次填充，实现自定），比例由运营商策略决定，不写"<1%"。

## 建议 5：隔离实例 + 诱饵前缀（替代伪造数据）

- 可疑会话经 KI#7.3 **重绑定到"无跨租户复用"的隔离 AIOF**：**结果真实**，仅失去共享、性能略降 → 误报不伤用户；
- 在其可见缓存中放置**诱饵前缀（canary）**；诱饵一旦被命中探测即获**高置信证据**，再按策略限速/撤权/通知 AF；
- 高交互蜜罐仅作为对"已确认恶意身份"的**可选威胁情报实施例**，不服务真实业务。

## 建议 6【新增专利点】：不触发重算风暴的域密钥轮换

- 问题：轮换 K_domain 会使全部缓存块不可寻址 → 重算风暴；
- 方案：采用**版本化域密钥 + 块级惰性重封装**：
  - 索引层引入 `key_version`；旧块在**被访问时**用旧密钥验证、用新密钥重封装索引（数据块不动），未访问块由后台按热度渐进迁移；
  - 对外只暴露统一查询接口，轮换期间新旧版本双读、写新；
- 效果：**密钥轮换与 KV 重算解耦**，轮换不引起算力尖峰。此点通用性强、易检测（索引/信令中存在 key_version 与双读行为），建议单列为一项核心从属/独立专利。

## 建议 7：暴露 / 选择 / 计费去相关子层（C2–C5）

- **指标暴露（C2/C3）**：启用跨租户复用的站点只允许 **#22.9 Variant A/E、#22.15 的抽象化暴露**；Variant B 的 TTFT、ms/token 须"聚合窗 ≥ T、按服务等级而非单节点、限频"；#19.4 Mechanism 2 的"负载→时间映射"只能基于**与缓存状态无关**的保守（按未命中）模型生成；
- **选择结果（C4）**：对消费者隐藏 AIOF/DNAI，只给 AISF 锚点；
- **计费（C5）**：对外按**逻辑 token 统一计价**，命中节省仅在运营商内部核算；用量报告按时间窗聚合；
- 该子层是**对 3GPP 最有说服力的增量**，建议写入 SA2 方案并作为独立从属权利要求群。

## 建议 8：完整性 / 迁移安全 / 合法监听 / 留存（合规闭环）

- **防投毒**：L0 共享块由生产 AIOF **签名/带完整性标签**；迁移链路提供机密性、完整性、重放保护；
- **迁移安全**：上下文迁移只在同复用域内建立，跨域重新派生/加密；
- **合法监听与留存**：声明 KV 块是用户内容的**派生物、非通信内容替代副本**；会话/许可结束后按策略删除；对接 TS 33.126；

## 建议 9：建立可复核的评估方法学
