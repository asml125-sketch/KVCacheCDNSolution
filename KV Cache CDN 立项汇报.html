01

为什么推理问题变成了 CDN 问题

四股力量，把 KV Cache 从引擎内存逼成了内容资产
💰经济学驱动 · 成本黑洞
Prefill 是算力吞噬者：让不同用户重复算同一份公共前缀（System Prompt、热门文档、工具定义），是对昂贵 GPU 的极大浪费——重复 Prefill 浪费 30–70%，复用是降 TCO 的唯一出路；回源代价是传统 CDN 的 100–1000×。
类比：每个用户都重算一遍「同一个开场白」，就是烧钱。
⏱性能驱动 · 延迟灾难
上下文 4K→128K→1M+，Prefill 从毫秒级跃升到数十秒（100K token 需约 10s），首字延迟彻底摧毁交互式应用体验。唯一解法「空间换时间」——KV 变成需预热、跨网分发、就近读取的「大文件」。
类比：每次提问先「发呆」十几秒，产品必被弃用。
🧱局部方案失效 · 三堵墙
单集群前缀缓存是「漏水的池子」：显存容量墙（并发一大撑爆 HBM，只能拒服务）、冷热驱逐墙（LRU 驱逐后陷「计算—驱逐—再计算」）、数据孤岛墙（集群 A 算过的前缀集群 B 无法复用）。
类比：单机显存是「水杯」，KV 是「消防栓」，一开就溢出。
🌐网络统计学驱动 · 统计复用
大数定律把多区域/多租户的长尾汇聚成「全局热点」，最大化命中率；叠加全球算力成本差 2–5× 与时区潮汐，在「夜间源站」集中 Prefill、「白天边缘」Decode，实现全球算力的 CDN 级调度。
类比：闲置算力变成全球「夜间的 Prefill 工厂」。
「问题成立，不等于『用带宽硬传』的解法成立。正确路径是 范式重构 —— 把 KV Cache 当作内容资产来运营。」

03

方案可行性 —— 关键结论

四条线测算：可行性成立，瓶颈在工程化与标准
⚡时间可行 · 拉取 vs 重算
100G 专线 + 4× 压缩，拉取 0.9s vs 本地重算 10s——11× 更快；落到 1G 公网则沦为 80s 灾难。
结论：跨域能否成立，取决于「带宽×压缩」胜过「字节×算力」；模型架构是第一杠杆。
📉解码收敛 · 向边缘移动
流式生成中 RTT 只加一次性偏移、不钳吞吐；多轮 Agent 循环则按轮数累积 RTT。
结论：两层拓扑（中心+区域）是更优默认，L0 仅在语音/合规/隔离场景加密。
🔬技术可行 · 三条线就位
模型侧（MLA/混合）、系统侧（池化/压缩/位置无关）、硬件侧（CXL/SmartNIC）均已成熟。
数字：Mooncake +525% / 115%、PrfaaS +54% / TTFT−64%、LMCache+vLLM +15×。
💎商业可行 · 场景成立
批发带宽下单请求成本降 64%，潮汐卸载降 55%；混合架构下零售带宽也成立。
结论：完整 CDN 形态 TCO −30~45%；适用边界：长上下文>20%、复用率>30%、区域成本差 2–5×。
可行性结论：成立 —— 三条技术线已就位、无不可逾越障碍；瓶颈在工程化与标准，这正是我们可卡位的窗口。
04

不做什么 · 做什么 · 怎么做

先划边界 → 定动作 → 再讲清凭什么的创新
✘ 不做「在 WAN 上实时硬传几十 GB 的完整 KV」——1 Gbps 下要 80 s，是灾难（§1.5 测算）。
✘ 不做「把缓存机械地放各地就完事」——而是让请求找数据（亲和路由）、让预分发只在划算时发生（经济博弈）。
✔ 做什么（核心五步：把 KV 当内容资产运营）
① 生产
中心 Prefill 算 KV、切段算指纹
② 上报
段 + Hash + 成本上报网关，累计热度
③ 决策
准入评分 + 博弈，定段 / 时刻 / 节点
④ 预分发
低谷异步推送高共享段到区域/边缘
⑤ 消费
亲和路由命中，仅算增量、TTFT 秒级
💡 怎么做 —— 三大创新点
①缓存亲和性路由
让请求找数据、而非数据找请求——按「复用程度 × SLA × 成本」把请求路由到复用最多、最合适的节点（方式 b 直连）。
②基于不同 KV 段的统计复用与分发
按共享度把 KV 切段、统计复用、差异化预分发到不同节点——不同节点持不同段，命中即免重算。
③经济与 SLA 博弈后的存算物理分离
每次跨域先算账：本节点推理 或 降级中心推理，博弈结果外显可取证——算存彻底解耦。

07

总结 —— 创新点与价值

三创新 · 三价值 · 请批资源
①缓存亲和性路由
是什么：全局网关像智能 DNS，按「复用程度 × SLA × 成本」把每个请求调度到"已算过这份上下文"的节点，客户端直连、不经网关转发。
带来什么：KB 级路由决策替代 GB 级 KV 传输，跨域硬传清零；命中节点只算增量，首字延迟 10s → 1–2s。
②基于不同 KV 段的统计复用与分发
是什么：把上下文按"多少人共用"切成独立寻址的段；统计每段的命中、共享度与区域热度，把高共享段在低谷期提前分发到位。
带来什么：一次 Prefill 多次消费，重复计算浪费降 30–70%；预分发成本不到单次硬传的 1/13。
③经济与 SLA 博弈后的存算物理分离
是什么：每次推理前实时估算"本地重算 / 跨域拉取 / 降级中心"三条路的耗时与价格，对照 SLA 择优——本节点推理，或上移中心完成。
带来什么：宁可重算绝不死等，恶劣网络下 SLA 仍可承诺；算存解耦，边缘可用更便宜的专用硬件。
🧑最终用户（ToC）体验：首字延迟 10s 级 → 1s 内（11×），长上下文、多轮 Agent 问答不再「等待思考」，接近本地应用的流畅度；成本：推理成本下降传导为普惠定价，长上下文场景单次成本降 64%，让用户「用得起」长上下文。
🏢服务提供商（运营商）成本：推理 TCO −30~45%——免每地域堆高配 GPU、边缘仅需低成本 Decode 硬件、低谷闲置算力变「夜间 Prefill 工厂」；业务：复用现有 CDN 机房与骨干专线，升级为「推理 CDN」新基础设施、面向企业 ToC 开展 MaaS；质量：博弈降级保障恶劣网络下 SLA 可承诺。
